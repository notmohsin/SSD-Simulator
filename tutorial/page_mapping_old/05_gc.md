## Overview

Garbage collection (GC) in page-level FTL mapping reclaims **full** physical blocks that are no longer writable (every page slot has been programmed at least once). The pipeline is:

```text
selectVictimBlock()  →  list of block indices
        ↓
doGarbageCollection()  →  read valid pages → update mappings → write to free block → erase victim
```

Victim selection is policy-driven (greedy, cost–benefit, random, d-choice). **How many** blocks to reclaim is driven by **GC mode** (`GC_MODE_0` fixed count vs `GC_MODE_1` threshold). During relocation, mapping updates go through `accessCMT(..., isWrite=true, isGC=true)` — see [Chapter 06](06_cmt_access.md).

## GC modes

| Mode | Name | Behaviour in `selectVictimBlock` |
| --- | --- | --- |
| `GC_MODE_0` | Fixed reclaim | `nBlocks` stays at `FTL_GC_RECLAIM_BLOCK` (default 1) |
| `GC_MODE_1` | Threshold reclaim | `nBlocks = totalPhysicalBlocks × threshold − nFreeBlocks` |

**Mode 1 intuition:** if the configured threshold says “keep at least 10% of blocks free” and you currently have too few free blocks, reclaim enough victims to close the gap.

**`bReclaimMore` bump:** if the last free block was fully consumed on the previous allocation, `nBlocks` is increased by `param.pageCountToMaxPerf` once (then the flag clears). This avoids stalling when the write pointer exhausts a block mid-burst.

## Eviction policies

| Policy | Weight formula (full blocks only) | Victim = |
| --- | --- | --- |
| `POLICY_GREEDY` | `validPageCount` | Lowest weight (fewest valid pages) |
| `POLICY_RANDOM` | `validPageCount` | Random sample of `nBlocks` entries, then lowest among sample |
| `POLICY_DCHOICE` | `validPageCount` | Random sample of `dChoiceParam × nBlocks` entries, then lowest |
| `POLICY_COST_BENEFIT` | `validRatio / ((1−validRatio) × age)` | Lowest weight (Greedy + recency) |

**Full-block filter:** every policy skips blocks where `getNextWritePageIndex() != pagesInBlock`. Only **sealed** blocks (no empty page slots left) are GC candidates. Partially written blocks are still receiving host writes.

**Cost–benefit detail:** `validRatio = validPages / pagesInBlock`, `age = tick − lastAccessedTime`. Weight = `validRatio / ((1 − validRatio) × age)`. High valid ratio → high numerator (worse victim). **Longer age → larger denominator → lower weight (better victim).** After ascending sort, the **smallest** weight wins.

**Edge cases (not guarded in code):**
- `validRatio == 1` (block still fully valid) → denominator has `(1 − temp) = 0` → division by zero / Inf.
- `age == 0` (last access at current `tick`) → same risk.
In practice sealed victims usually have some invalid pages and non-zero age; still worth knowing if you enable `POLICY_COST_BENEFIT`.

---

## Invariants (GC path)

1. **Victim list ⊆ sealed blocks.** Partial blocks never appear in `weight`.
2. **Sort order.** After `std::sort`, `weight[0]` has the minimum score; victims are taken from the front.
3. **Random/d-choice dedup.** Sampled entries are marked with `first = UINT32_MAX` so the same block is not picked twice in one selection pass.
4. **GC mapping coherence.** Every relocated LPN updates mapping through `accessCMT` with `isWrite=true` and `isGC=true` — dirty CMT entries, GC-specific hit/miss stats.
5. **I/O ordering.** All reads complete (tracked at `readFinishedAt`), then writes start at `readFinishedAt`, then erases start at `readFinishedAt` (not `writeFinishedAt`). Final `tick` is `MAX(writeFinishedAt, eraseFinishedAt)`.
6. **Erase always queued.** Even an all-invalid victim block still gets an erase request.

**GC → erase handoff:** `doGarbageCollection` only **queues** victim block indices and calls `eraseInternal` (ch. 07). That helper is what actually erases NAND via PAL, bumps erase-count / wear ordering, removes the block from `blocks`, and reinserts it into `freeBlocks` / increments `nFreeBlocks`. Without that call, relocated data would exist but free-block supply would never recover.

## GC ↔ CMT interaction (summary)

```text
Host write path:  accessCMT(lpn, isWrite=true,  isGC=false)
GC relocate path: accessCMT(lpn, isWrite=true,  isGC=true)
Host read path:   accessCMT(lpn, isWrite=false, isGC=false, allocate=false)
```

Effects of GC on CMT:

- **Hit:** promotes LRU position or LFU frequency (same as user access); `cmtGCHits++`
- **Miss:** may evict another entry (with possible dirty write-back); `cmtGCMisses++`; may pay `cmtMissLatency`
- **Dirty:** relocation always passes `isWrite=true`, so the entry becomes dirty
- **User hit rate:** GC counters are excluded from `cmt.hit_rate` in stats export

## Self-quiz — answers

1. Only **sealed** blocks: `getNextWritePageIndex() == pagesInBlock`.
2. Mode 1 sets `nBlocks = totalPhysicalBlocks × reclaimThreshold − nFreeBlocks` to restore a target free-block fraction; mode 0 uses the fixed `GCReclaimBlock` config value.
3. Random/d-choice only randomizes **which** candidates are compared; the score is still valid-page count (greedy), so the lowest-valid block among the sample wins.
4. It marks an already-selected index so the sampling loop cannot pick the same block twice.
5. The **front** — lowest weight after ascending sort (`weight[0]`, `weight[1]`, …).
6. It adds `pageCountToMaxPerf` to `nBlocks` once when the previous allocation exhausted the last free block; the flag is cleared after use (set in free-block allocation — Chapter 04).
7. Comment at 769–770: avoids PAL2 limitations (SIGSEGV / infinite loop) when interleaving requests inline.
8. `accessCMT(lpn, isWrite=true, tick, isGC=true)`; on miss, `stat.cmtGCMisses++` (and possibly eviction, write-back, `cmtMissLatency`).
9. **No** — erases use `beginAt = readFinishedAt`, same as writes, not `writeFinishedAt`. Final `tick` is the max of write and erase finish times.
10. Immediate return at line 690–692; no I/O, no stat changes, no tick advance beyond what the caller already applied.
